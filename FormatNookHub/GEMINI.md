\# FormatNook - Project Instructions



\## 1. Mandatory Development Guidelines



Before starting any development task, read and follow `KARPATHY\_GUIDELINES.md`.



Apply all four principles:



1\. Think Before Coding

2\. Simplicity First

3\. Surgical Changes

4\. Goal-Driven Execution



\## 2. Existing Project Protection



\- Understand the existing project architecture before making changes.

\- Never rewrite existing functionality unnecessarily.

\- Do not modify unrelated files.

\- Preserve existing features, routes, APIs and components.

\- Follow existing coding conventions and folder structure.

\- Do not introduce unnecessary dependencies.

\- Never replace working implementations without justification.



\## 3. Development Workflow



For every non-trivial task:



1\. Understand the requirement.

2\. Inspect relevant existing files.

3\. Identify dependencies and potential side effects.

4\. Present a short implementation plan.

5\. Implement the minimum necessary changes.

6\. Add or update relevant test cases.

7\. Run tests, lint and build where applicable.

8\. Fix issues introduced by your changes.

9\. Summarize modified files and verification results.



\## 4. Quality Standards



\- Write clean, maintainable, production-quality code.

\- Prioritize performance, security and accessibility.

\- Avoid duplicate logic.

\- Avoid unnecessary abstractions.

\- Handle realistic edge cases.

\- Never claim tests passed without actually running them.



\## 5. Important Rule



Do not start implementation when critical requirements are ambiguous.



Ask for clarification rather than making risky assumptions.



Existing project functionality must remain intact unless explicitly requested otherwise.
